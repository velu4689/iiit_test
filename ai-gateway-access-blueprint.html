AI Gateway Access Blueprint

How developers in three AWS Control Tower landing zones reach the TrueFoundry data planes from Kiro, and how their applications reach them after they ship. There are no developer groups in Okta and no static keys on laptops. Every token lands on a team's virtual account, which is where cost is counted.

Okta

One org and four shared authorization servers: non-prod, non-prod CPNI, prod and prod CPNI. No developer groups.

TrueFoundry

Two tenants. The non-prod tenant trusts only the non-prod servers, and the prod tenant trusts only the prod servers.

Developer path

An SSM tunnel through a bastion in each tower's non-prod data planes, allowed by the developer permission set they already have.

Cost

One virtual account per team per environment for development, and one per application per environment. Spend is counted per team, not per developer.

      Developer access token, copied off the laptopUsing it needs a tunnel, and a tunnel needs AWS access to that tower. The token expires within 60 minutes.Usually nothing. To be sure, revoke the user's Okta sessions.
      
        
      A non-prod token used against prodThe prod tenant trusts only aus-prod and aus-prod-cpni. Developers have no client on those servers and no tunnel into prod.No action needed. It is rejected at the gateway.

The bastion only ever carries TLS-encrypted bytes.No action needed. CloudTrail records each session start.
      
        
      Non-CPNI developer tries CPNIThe CPNI tunnel works only through the WorkSpaces VPC endpoint. Non-CPNI virtual accounts have no grants on CPNI models.No action needed. It is denied at two layers.

      Add to the existing developer permission set (each tower)
      
      
      Developers already reach EC2 through SSM. These statements add the tunnel on the bastion. With SessionDocumentAccessCheck, a session on the bastion must name a document the caller is allowed, and only the tunnel document is allowed there. Where existing shell rights cover all instances, add the StringNotEquals condition shown at the end so they skip the bastion.
      

      {
  "Sid": "TunnelOnTaggedBastion",
  "Effect": "Allow",
  "Action": "ssm:StartSession",
  "Resource": [
    "arn:aws:ec2:<region>:<dataplane-account>:instance/*",
    "arn:aws:ssm:<region>:<dataplane-account>:document/TFY-GatewayTunnel-nonprod"
  ],
  "Condition": {
    "StringEqualsIfExists": { "ssm:resourceTag/role": "ai-gw-bastion" },
    "BoolIfExists": { "ssm:SessionDocumentAccessCheck": "true" }
  }
},
{
  "Sid": "FindBastion",
  "Effect": "Allow",
  "Action": "ec2:DescribeInstances",
  "Resource": "*"
}

// CPNI tunnel: also require the WorkSpaces VPC endpoint
//   "StringEquals": { "aws:SourceVpce": "vpce-<workspaces-ssm-endpoint>" }
// Existing shell statement: keep it off the bastion

      SSM document: TFY-GatewayTunnel-nonprod
      
      
      The host and remote port are fixed in the document, so a tunnel can reach only the gateway. Create one per non-prod data plane, in each tower.
      

      {
  "schemaVersion": "1.0",
  "description": "Tunnel to the TrueFoundry non-prod gateway only",
  "sessionType": "Port",
  "parameters": {
    "localPortNumber": { "type": "String", "default": "443", "allowedPattern": "^[0-9]{1,5}$" }
  },
  "properties": {
    "type": "LocalPortForwarding",
    "host": "ai-gw-nonprod.ct1.corp.internal",
    "portNumber": "443",
    "localPortNumber": "{{ localPortNumber }}"
  }
}
